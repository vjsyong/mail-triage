## 1. Gemma 4 family (Google DeepMind, released 2026-04-02)
- Five sizes across four architectures: **E2B (2.3B eff), E4B (4.5B eff),
  12B Unified (11.95B), 26B-A4B (MoE, 3.8B active), 31B dense**. Apache 2.0.
- Vision on all; **audio on E2B/E4B/12B**; configurable **thinking modes**;
  native **function-calling support** ("Enhanced Coding & Agentic Capabilities");
  E2B/E4B 128K ctx, 12B/26B/31B 256K (per cards).
- Google's τ²-bench (agentic): 26B-A4B 68.2 · 31B 76.9 · **12B 69.0** · E4B 42.2 · E2B 24.5.
- Official **QAT checkpoints** exist (q4_0 GGUF + `-qat-w4a16-ct` for vLLM/compressed-tensors).
- Sources: https://huggingface.co/google/gemma-4-E4B-it ·
  https://huggingface.co/google/gemma-4-12B-it ·
  https://daily.dev/posts/gemma-4-model-family-sizes-architectures-and-when-to-use-open-models-36wtvfnft
  (retrieved 2026-10-02) · Ollama: https://ollama.com/library/gemma4

## 2. Qwen3.5 (Alibaba, released 2026-02-24→28)
- Sizes: **0.8B / 2B / 4B / 9B dense** + 27B dense + 35B-A3B MoE + 122B-A10B +
  397B-A17B. Apache 2.0. **262K native ctx** (extensible ~1M).
- Hybrid architecture (Gated DeltaNet + Gated Attention), MTP-trained,
  multimodal (vision), thinking mode, tool calling. On this host vLLM v0.22.0
  already supports the architecture (`Qwen3_5ForConditionalGeneration`).
- Vendor benchmarks (model cards): **BFCL-V4: 9B 66.1, 4B 50.3** (vs Qwen3-30B-A3B
  42.4, Qwen3-Next-80B 49.7); τ²-bench: 9B 79.1, 4B 79.9; IFEval 91.5/89.8;
  MMLU-Pro 82.5/79.1. Download volumes: 9B ~9.3M, 4B ~7.5M (top-tier adoption).
- Sources: https://huggingface.co/Qwen/Qwen3.5-9B ·
  https://huggingface.co/Qwen/Qwen3.5-4B · https://huggingface.co/Qwen/Qwen3.5-2B
  (retrieved 2026-10-02). Community 4-bit quants exist (e.g. cyankiwi AWQ-4bit).

## 4. LFM2.5 (Liquid AI, 2026-05→09)
- Sizes: 230M / 350M / 1.2B / **2.6B dense** / **8B-A1B MoE (8.3B total, 1.5B
  active)** / VL-3B. License: LFM Open License 1.0 (**not** Apache; free tier
  has revenue conditions — check before commercial deployment). 128K ctx.
- Hybrid short-conv + GQA; **agentic post-training** ("trained inside popular
  agentic harnesses"; "competitive with models 4× larger on tool use");
  tool calls default to a Pythonic format (JSON override possible); day-one
  support llama.cpp / MLX / vLLM / SGLang.
- Sources: https://huggingface.co/LiquidAI/LFM2.5-8B-A1B ·
  https://huggingface.co/LiquidAI/LFM2.5-2.6B (retrieved 2026-10-02).

## 7. What the evidence says for THIS app
- The task domain is **structured classification (JSON, every message) +
  tool-calling agent + drafting**. Structured-output/tool reliability is the
  make-or-break axis, not trivia recall.
- Three lines of evidence converge on a promising band: **~3-9B current-gen
  models with native thinking + tool calling** (Qwen3.5 smalls, Granite 4.2,
  Gemma 4 smalls, LFM2.5).
- 2B-class models (MiniCPM5, Qwen3.5-2B, LFM2.5-2.6B, gemma-4-E2B) exist and
  keep improving, but every independent/vendor signal still puts them well below
  4B-class on instruction following and agentic tasks → kept as reserves only.
- All shortlisted checkpoints load on the SAME vLLM version as production
  (v0.22.0) → clean, same-runtime comparison.
