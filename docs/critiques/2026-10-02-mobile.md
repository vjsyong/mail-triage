## Verdicts — one line per screen

- **dashboard — better vs the P2 §1 dashboard bar (Vercel-style stats).** The hero ("938 — need a reply · view →") answers one question and links to the list it summarizes; "Last check 29s ago" + "Check now" is exactly the P1 §6 freshness/manual-refresh pair; and "Recent filings — Undo puts one back and keeps automation off it" is a trust pattern that none of P1's peers ships inline at a machine move. Faults (nits 3–4): the recent list shows ~one row above the tab bar, two stat rows stay inert while their neighbours link, and a "Settings →" link sits inside a stat card.
- **messages — worse vs the Gmail/Spark list bar (P1 §1).** The machine chips (`SORTED`, `LLM → FOLDER`, `Notification 97%`) answer "where did it go" better than any consumer list, and 7 filter chips clear the "≥2 scoping axes" bar; but rows carry no read/unread affordance (read items don't recede), there is no search or unread axis, and "page 1 of 36" puts pagination where Gmail/Spark/Superhuman run continuous lists.
- **viewer — worse vs the Fastmail/HEY reading-pane bar (P1 §3).** "← Newer / Older →" now exists (new since 10-01), but on mobile the action card — File to X / Re-classify / Tag / No reply needed / Snooze 1d·3d·1w — stacks **below the message body** (`.msgrid` collapses to one column under 1024px, app.py:4027), so acting on a long newsletter means scrolling past the whole email; there is no reply control, no archive-and-advance, and no "reply to each, then next" queue mode.
- **assistant — par vs Shortwave/Gemini's chat surface (P1 §5).** Icon + one-line purpose + four starters + composer is the right empty state, and the source shows page-aware starter banks ("Which need replies?", "Oldest unread" for messages — app.py:5034). The two things the bar actually demands — confirm + undo on proposed mutations — cannot be verified from a still; the hamburger's purpose is undiscoverable from one either (flagged, not charged).
- **rules — better vs the Gmail/Outlook/Zapier rule-builder bar (P2 §2).** Numbered, ordered rules with per-rule reorder (incl. move-to-top), non-destructive "disable", guard rules ("keep in place"), and two dry runs exposed before commit — "Test against last 200 messages" (Outlook's run-on-existing) and "Simulate a draft" (Zapier's test step). Testing before commit is the thing most peers hide; this screen leads with it.
- **settings — par vs the HIG settings model (P2 §5).** Task-named tabs, values visible without tapping ("Sean", "8.0", checked), each setting with a one-line explanation; faults: a raw decimal timezone field, a tab row cutting "Classi…" mid-word, and a button-per-section save instead of autosave.
- **more — par vs HIG (P2 §5).** Automation / System groups, every row with a one-line description, long-tail destinations in More exactly as HIG prescribes; nothing needs to move. It is also the honest home for Rules — though Rules are the product's engine, so one fewer hop would be worth something (nit 9).
- **log — par vs Vercel runtime logs (P2 §3).** Search ("Filter lines…" + Find) and Pause are new since 10-01 and close half the gap; UTC+8 is stated in the header, rows are newest-first, monospace, severity in text+colour. Still missing: a time-window filter, a visible live indicator (only "Pause" implies it), and per-row copy affordances for IDs.

## Top gaps vs the commercial bar

1. **Undo doesn't travel to where the action is taken.** The only undo control rendered anywhere is the dashboard's "Recent filings" form (app.py:2166 — the sole `undo_move` usage in the app); the log records the undo trail but offers no button, and bulk actions in the list don't either. *Best:* Fastmail's 10-action undo stack and Gmail Gemini's 60s undo at the point of action (P1 §2/§5 bars). *Why it matters:* mistakes are noticed where mail lives — a row in the list, a message you just read — not on a dashboard widget showing one move.
2. **The reading pane can't run the triage loop.** Actions sit below the body, there's no reply control (drafting lives in the assistant/Templates), no archive-and-advance, no "focus and reply" mode. *Best:* Fastmail's `[`/`]` archive-and-move-on and HEY's Focus & Reply ("knock out 5 of 12, or all 12, or none") (P1 §3 bar). *Why it matters:* "Needs reply 938" is a queue in name only if draining it costs scroll-past-the-body + back-navigate per message.
3. **The list can't express state.** No unread dot, no recede for read/handled rows (every sender is uniform 600 weight), and no read/unread axis among the 7 chips — even though the data exists (the app's own mail tools set `\Seen` and list unseen counts, engine.py:2626–2637). *Best:* Gmail/Spark unread weight + Seen-section recede; HEY's Imbox. *Why it matters:* with 3,591 messages and 99% LLM coverage, the list is where the user audits what the machine did; today every row reads as new.
4. **Search exists only as chat.** The list has no query axis; "Find an old invoice" is an assistant chip. *Best:* Gmail/HEY/Fastmail search-in-list (and Fastmail turns any search result into a rule — P2 §2's "search → rule" path). *Why it matters:* a chat answer returns prose, not a scoped, actionable list — you can't bulk-act on a paragraph, and you can't see the neighbours of the hit.
5. **Machine vocabulary at the trust moments.** `SORTED`, `MOVE:NEWSLETTERS`, `LLM → FOLDER`, "Auto-filing ON", "keep in place (guard)" — caps-and-colon tokens exactly where the user must decide whether to trust or undo the machine. *Best:* HEY's plain-language model (Imbox / Paper Trail) and P2 §4's plain-label rule. *Why it matters:* the app already computes the explanation ("why: …", full LLM reasoning in the audit card, app.py:4121) — the surface just doesn't speak it.

## Summary

- The automation-faith story is now credible: undo trail with re-file guard, snooze that resurfaces, a dry-run-first rule editor — all three beat or match the bars their peers are held to.
- What's left is the *human* loop: the list can't show what you've read or handled, the viewer can't act on what you're reading without a scroll, and search is chat-only. The machine side of triage is strong; the person side is thin.
- The log and settings are at par with only small deltas (time window, live indicator; a zone picker) — they need rounding, not rethinking.
- Highest-leverage change: a sticky action footer on the viewer (File · reply-from-template · snooze · undo the last move). It closes gaps 1 and 2 in one pattern and turns "needs reply 938" from a filter into a loop.
- None of the 12 nits are blockers; the three majors are all the same theme — actions and state living one layer away from where the user is looking.
