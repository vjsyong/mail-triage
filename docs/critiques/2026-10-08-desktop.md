## Top gaps vs the commercial bar

1. **No path from a search to a rule or a saved view.** Best: Fastmail — any search result can become a rule [P2 §2, ref 12]; Gmail — build a filter from search criteria and test the search before committing [ref 11]; Shortwave ships custom-query Splits [P1 §1]. We: the search card (6294-6306) produces ephemeral results, and rules are built by hand on /rules; the only bridges are the auto-mined tag→rule proposals card (6255-6276) and asking the assistant in chat. Why it matters: the automation payoff is the loop "I keep seeing this pattern → encode it once"; every forced re-transcription of the criteria breaks that loop at the exact moment the user is looking at the evidence.
2. **After commit, automation is unobservable.** Best: Zapier — every run lands in Zap History [ref 15]; Outlook can run a rule on existing messages [ref 13]. We: the dry-run gives per-rule counts once (2900-2906) and they vanish; the rules table is #/rule/if/actions with no matches/last-fired column (2912). Why it matters: 12+ live rules file mail silently; you cannot tell a dead rule from a load-bearing one, yet the app rightly treats per-message provenance as a feature (audit trail) — rules deserve the same.
3. **The default list scope is a state soup.** Best: Spark sinks read mail into a "Seen" section; HEY keeps the Paper Trail out of the Imbox; Superhuman partitions Split Inboxes [all P1 §1]. We: the default "All" chip counts the whole mailbox — 3,651 — of which 2,597 are already rule-sorted, and the top rows interleave CLASSIFIED and SENT mail in one chronological stream. Why it matters: the default view is where triage starts, and ~71% of what it shows is already handled mail sitting in the scan path. (Fresh angle: the default scope, not the already-logged row-action items.)
4. **Verdicts never reconcile at the conversation level.** Best: Gmail — the thread is the unit with one reading/status model [P1 §1, §3]. We (today's shots): one conversation ("…Document upload problem") appears as four rows; two student mails minutes apart carry different categories (Personal 95% vs Action 95%) and reply state is per-row; nothing merges the conversation's state. Why it matters: label trust dies at the first visible contradiction inside a thread; the triager then re-reads everything. (Fresh angle: thread-level *state*, not the already-logged row-collapsing interaction.)
5. **Deadlines inside mail are summarized, never surfaced.** Best: Gmail Gemini adds "Add to calendar" above the email when an event is detected [P1 §3]. We: today's viewer summarizes "expires Oct 23, 2026 … must be renewed" and the list shows "download them ASAP", but no deadline affordance (add-to-calendar, due chip, remind-me) is visible in any of the eight reviewed screens. Why it matters: this mailbox's dominant genre is deadline mail (renewals, Zoom deletions, payroll) — after reading, the next action is usually scheduling, and leaving it to memory wastes the summary. (Opinion/opportunity, not a bar violation.)

## Nits

1. **minor — viewer — "Audit trail · 1 events".** The collapsed summary is un-pluralized — `{{ m.audit|length }} events` (6758) — while the expanded body already does it right ("1 event", 6759). Source: the app's own plural convention (2487) / P2 §1 text quality. Fix: reuse the conditional in the `<summary>`.
2. **minor — assistant — same-day sessions are indistinguishable.** Two 10-05 chats both render "Find me messages related to…" (rows show title + date only; tooltip repeats the full title — 7605-7609), and a second pair shares "What rules would you suggest for my…". Source: P2 §8 (every micro-detail deliberate). Fix: show time-of-day and/or a one-line snippet, or disambiguate the stored titles.
3. **minor — messages — the TAG column is dead width on the default view.** `<th>tag</th>` renders regardless (6339); on today's page every cell is empty (Tagged 0), and the column only auto-hides below 1400px (6244), so at 1440px it shows nothing. Source: P1 §1 (scan cost is the core cost). Fix: hide the column when the page has no tags, or render tags inline under the subject.
4. **nit — assistant — mutation permissions are one disclosure deep.** "Can do directly / Asks first / Off" live inside the collapsed "assistant details" (7660-7667); the bar wants agentic permissions "opt-in and visible" (P1 §8; §5(c)). Fix: a one-line scope summary (e.g. "2 actions ask first") outside the fold.
5. **nit — dashboard — "0 pending approvals" is a zero-value KPI.** The attention hero renders all three counters even when one is zero (2488), so the strip advertises nothing to do; P2 §1 calls KPI tiles that answer no user question an anti-pattern. Fix: drop zero counters (the all-zero case already has its own caught-up line, 2489).
6. **nit — messages — no manual refresh on the list page.** "Check now" exists on the dashboard (2470) and in the messages empty state (6359) only; the head shows just count + page (6252). P1 §6 bar: visible freshness + manual refresh (Fastmail `u`). Fix: a small refresh control beside the count or in the sidebar footer.

## Summary

- 8 screens reviewed: 2 better than peer bar (rules, accounts), 5 par (dashboard, viewer, assistant, settings, classifiers), 1 worse (messages).
- The desktop app is a strong *record* surface — provenance, verification, status wording — and a weak *conversation* surface: no thread-level state, no inbox-vs-archive default scope.
- Five fresh gaps: search→rule pipeline, rule run observability, state-soup default list, thread-level verdicts, deadline surfacing.
- One new verified defect class: un-pluralized audit summary ("1 events", app.py:6758); yesterday's three fixes (2487, 3484, 3486) confirmed landed.
- Biggest single-leverage fix: wire "Save as rule"/proposals into any filtered list, and add per-rule counters to the rules table.
