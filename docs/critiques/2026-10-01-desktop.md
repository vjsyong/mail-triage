Set: dashboard, messages, viewer, assistant, rules, settings, classifiers, accounts (`qa/shots/2026-10-01/desktop/`).
Method: one inspection pass per screenshot + 4 zoom crops (budget exhausted: viewer body, assistant composer, classifiers table, dashboard top-right). Design invariants (square corners, light Vercel theme, Geist, black log panels, blue links) are deliberate and are NOT flagged.

## Findings (ordered by severity)

### 1. [major — escalate to blocker if reproducible] viewer.png · message body column
- **Element:** email body block (`.emailbody` / `.msgbody`, app.py L3634–L3678).
- **Wrong:** the body text stops mid-word at the right boundary of the body column instead of wrapping — e.g. "You're signed up to receive a **da**", "Late Assignment: ZHANG, **Ze**" — characters look lost, not wrapped. Raw HTML email is injected with only `max-width:100%` guards on `img`/`table`, so content wider than the column can overflow/clip instead of reflowing.
- **Source:** research-lists §Shared rules #1 (never let a squeezed container destroy legibility) + WCAG AA (no loss of content).
- **Fix:** make the body container a wrapping/scrollable one (verify no ancestor clips; keep `overflow-x:auto` effective on `.emailbody`) and re-shoot with a known-wide HTML email. Vision-only verification (two passes agree); confirm in browser before treating as blocker.

### 2. [minor] assistant.png · chat-history rail
- **Element:** left history column rows (`.assistant-rail .arow .t`, app.py L680 — `nowrap + ellipsis`, no min-width headroom).
- **Wrong:** nearly every conversation title is ellipsized to a near-identical fragment ("Search my mail …" ×3, "I want a flow su…" ×2, "What rules wou…", "Reply with exact…" ×2), so entries can't be told apart without opening each; the timestamp and the "×" delete control sit hard against the truncated text.
- **Source:** research-lists §Shared rules #2/#4 (row L1 identity must stay readable and scannable; M3 *Lists*).
- **Fix:** give the rail more width and/or allow a 2-line clamp on titles (reuse the messages `-webkit-line-clamp` pattern), keep the full title in `title=`.

### 3. [minor] rules.png · MATCHES column
- **Element:** rule match-summary cells (global `.mono{word-break:break-all}` — app.py L373–L374).
- **Wrong:** condition strings break at arbitrary characters: "subject contains \"Newsl etter\"", "jac.leun g@ust.hk", "O R". Boolean operators and addresses read as different tokens on the page whose whole job is reading conditions correctly.
- **Source:** research-lists §/rules (the match summary "is a sentence, not ellipsis fodder") + Shared rules #1.
- **Fix:** drop `break-all` for the match cell (use `overflow-wrap:anywhere`), so breaks prefer spaces/operators and only split a word when unavoidable.

### 4. [minor] classifiers.png · KIND column
- **Element:** `kind` cell (`<td class="mono">`, app.py L2097) under the same `break-all` rule.
- **Wrong:** `decision_list` appears fragmented across ~4 lines ("deci / sion / _lis / t") — the reference column is squeezed below a readable token width instead of being de-emphasised.
- **Source:** research-lists §/classifiers ("kind and matches on are reference" — treat as secondary, don't cram) + Shared rules #1.
- **Fix:** `white-space:normal; overflow-wrap:anywhere` (or a sensible min-width) for the kind cell, or move `kind` into the row-detail per the brief.

### 5. [minor] messages.png + dashboard.png · truncated values carry no cue
- **Element:** server-side slices rendered without ellipsis: `m.from_addr[:34]`, `m.subject[:84]`, `m.llm_summary[:150]` (app.py L3388–L3390; same family on the dashboard Recent-mail table).
- **Wrong:** over-long addresses/subjects simply stop mid-word (dashboard Recent mail shows the `notifications@instructure.com` row cut at the column) — the user cannot tell whether the value is complete.
- **Source:** research-lists §Shared rules #2 (row identity) and #8 (truncation must be signalled/contextual, uxpatterns.dev via ui-redesign).
- **Fix:** append "…" when a slice actually truncates (or clamp in CSS so the ellipsis is rendered) and add `title="{{ full value }}"`.

### 6. [nit] messages.png · subject/snippet rows
- **Element:** subject cell with `llm_summary` sub-line (app.py L3389–L3390).
- **Wrong:** on the long Press-Release row the subject wraps to ~5 lines with the summary running directly beneath it, no separation, while adjacent rows are 1 line — row-to-row rhythm breaks and the two texts read as one block.
- **Source:** research-lists §Shared rules #2 (one fact per line; consistent element order per row).
- **Fix:** clamp the subject to 2 lines on list rows (existing line-clamp convention) and keep the snippet as its own dim line with a small top margin.

### 7. [nit] assistant.png · composer footer
- **Element:** permissions helper line (app.py L4341; the blue `edit` is a deliberate link to `settings#ai-perms`).
- **Wrong:** the wrap leaves `edit` alone on the last line, directly under "disabled: delete, send", so it reads as a fourth disabled capability rather than a link to change permissions.
- **Source:** research-forms §6 (state must be unmistakable in visible text, not adjacent ambiguity).
- **Fix:** keep the link attached to its sentence (non-breaking group) or move it before the capability lists ("agent permissions: … · edit").

### 8. [nit] settings.png · LLM-endpoint fields
- **Element:** "Base URL" and "Model" inputs in the LLM endpoint card.
- **Wrong:** both stretch the full card width (~900px) for short values (~30 chars), so the card is mostly empty field space.
- **Source:** research-forms §1 Desktop ("size fields to the expected input where cheap").
- **Fix:** cap these inputs at a length proportional to their content (≈360–420px).

### 9. [nit] rules.png (and the rail on other pages) · "»" toggle
- **Element:** assistant-rail header collapse control (glyph-only "»").
- **Wrong:** appears unlabelled (no visible text; tooltip/aria-label not confirmable from shots) and on the rules shot it looks half-clipped at the right viewport edge.
- **Source:** research-shell §1/§4 (controls must be labelled and unambiguous; same consistency spirit as the shell conventions).
- **Fix:** add `aria-label`/`title` ("Collapse assistant") and ensure the rail header keeps enough right padding that the control never clips at 1440px.

## Checked and dismissed (NOT defects)
- messages.png "no pagination controls": false positive — `.pager` (← Newer / Older → / Last » / page X of Y / per-page chips) renders after the table at L3405–L3413; at per-page 100 the 3555-message list simply puts it below the visible rows.
- viewer.png From-address breaking mid-domain: deliberate `overflow-wrap:anywhere` on `.msgfrom` (L3631) so long addresses can't overflow the Details column.
- settings.png "Always load" checkbox sitting far from its label: that is the intended `.setrow` two-column settings idiom (research-forms §1 Desktop), not a misalignment.

## Summary (desktop, 1440×900)
1. 9 findings: 1 major (viewer body text clips mid-word — verify in browser; blocker if reproducible), 4 minor (assistant history titles unreadable; rules/classifiers mono columns break words char-by-char via `break-all`; sliced fields truncate with no "…" cue), 4 nits.
2. Highest-value quick fixes: `word-break:break-all` → `overflow-wrap:anywhere` for mono data cells; clamp + ellipsis for history titles and list subjects.
3. Structural suspect for the viewer: raw HTML email injected under `.msgbody/.emailbody` with only `max-width` limits.
4. Two early suspicions were disproven by reading `app.py` (pager exists below the fold; the `edit` token is a deliberate link) and are recorded above so they don't get re-flagged.
