# Mobile critique — 2026-10-04

Screens judged: dashboard, messages, viewer, assistant, rules, settings, more, log (393×852@2x).
Yardstick: `docs/ux-benchmarks.md` (Part 1 = P1 §1–8, Part 2 = P2 §1–8) + `dashboard-mobile.md` / `messages-mobile.md` briefs. Verdicts: worse / par / better. "Verify" marks claims the loop driver should confirm before fixing (no pixel forensics asserted).

## Verdicts

- **dashboard — par** vs the dashboard bar (P2 §1 — Pencil&Paper/UX Pilot questions + Vercel status conventions) — hero "0 need a reply" answers the screen's one question and links to its filtered list; the 2×2 status chips carry text, not color alone; "Last check 44s ago" + "Check now" beat the bar's freshness minimum. Held back by "All systems normal" while the log shows same-day ERRORs (verify) and the Settings→ chip inside the status grid.
- **messages — worse** vs Gmail/Spark list bar (P1 §1) — row anatomy (sender / time / subject / badge) is clean and there are 4 scoping axes (All / Awaiting LLM / Needs reply / Sorted+ with honest pagination "page 1 of 37"), but three THE BAR items fail: no unread affordance is visible (verify), no one-gesture row action, and repeated senders (Canvas ×2) never collapse.
- **viewer — worse** vs Gmail/HEY/Spark reading-pane bar (P1 §3) — the only controls are "← Newer / Older →"; no reply / reply-all / forward, no archive / snooze / mark-handled, no undo beside the "MOVED TO CANVAS" badge, no audit trail. Triage decisions can't be taken — or reversed — where the mail is read.
- **assistant — par** (on the visible surface) vs Gmail Gemini / Shortwave (P1 §5) — clean welcome ("Ask about your mail") with 4 starter prompts and unusual model transparency ("mimo-v2.6-9b · assistant details"). The bar's two real tests — inline summarize/draft on an open message, and confirm + ≥60s-undo gates on mutations — can't be seen from the empty state (verify).
- **rules — better** vs Outlook/Gmail filter builders (P2 §2) — numbered, ordered rules with monospace conditions, non-destructive toggles, ellipsis for more — plus page-level dry-runs ("Test against last 200 messages", "Simulate a draft") that meet the Zapier/Gmail test-before-commit bar almost nobody offers on mobile.
- **settings — par** vs Gmail/Spark General (P1 §7, P2 §5) — task-named tabs (General / AI Settings / Language model / …), plain visible labels above inputs with helper text, current values shown, explicit "Save general". Caveats: 4th tab cut mid-word, save-status announcement not verifiable from a still (verify).
- **more — better** vs HIG settings/More guidance (P2 §5, ref [7]) — textbook long-tail hub: grouped AUTOMATION / SYSTEM with one-line descriptions per destination, core triage actions correctly kept out of Settings. Wrinkle: "Get started" checklist still pinned at top while mailbox/LLM/search are live (verify completion state).
- **log — better** vs Vercel runtime logs (P2 §3) — newest-first timeline, severity as labeled badges (INFO/ERROR/PLUGIN — text, not color alone), timezone + "debug lines hidden" stated, "Filter lines…" search, and a Pause button = pausable auto-follow (WCAG 2.2.2). Filtering is par-minus: no time-window chip visible (verify).

## Top gaps vs the commercial bar

1. **The reader can't act.** No reply/archive/snooze in the viewer; the machine "MOVED TO CANVAS" and its Undo exists only on the dashboard's Recent filings. Best: Gmail (inline actions + auto-advance), HEY Focus & Reply, Spark swipes. Why it matters for a triage app: decisions land at the open message — make the user leave the reader (or hunt the dashboard) to reply or take a move back and the product's fastest loop disappears. (P1 §2–§3 — could also run reply-later as a queue like HEY.)
2. **The list has no one-gesture triage.** Selection checkboxes + bulk buttons only; no configurable row swipe / quick action (archive, move, read, snooze), no visible select-all/range. Best: Gmail per-direction swipe incl. "None", Spark pin/snooze swipes, Shortwave. Why: phone triage is gesture-first; checkbox-then-toolbar is the desktop brain transplanted. (P1 §1–§2; WCAG 2.5.7 is satisfied by the checkbox path, so this is speed, not an AA failure.)
3. **Read/handled state doesn't surface in the list.** Rows show no unread marker and read items don't visually recede (verify) — after classification, "SORTED/CLASSIFIED" badges are the only state encoded. Best: Gmail (unread bold, read recede), Spark's Seen section. Why: the list's only job is "what still needs me"; without state, every scan re-reads the whole page. (P1 §1 THE BAR.)
4. **Assistant is a destination, not a layer.** No inline summarize/draft visible anywhere on the open message; the chat's mutation gate (confirm + ≥60s undo) can't be confirmed from the empty state (verify). Best: Gmail Gemini (inline + side panel, explicit confirm, 60s undo), Shortwave ("any email on your screen"). Why: the benchmark's two-surface bar — inline is where AI drafts get accepted, chat is where mailbox-wide work gets planned; one without the other halves the value. (P1 §5.)
5. **Status honesty is unproven cross-screen.** Dashboard reads "All systems normal / Last check 44s ago" while the log records same-day ERRORs ("indexer failed" 10-04 03:01, "check failed" 10-04 00:36) — verify whether they self-resolved; if green ignores recent failures, the exception-first promise ("auto-opens whenever anything is off" — dashboard brief) is broken. Best: Vercel (4xx amber / 5xx red; a status surface names state + action). Why: "is mail actually being handled right now?" is the dashboard's entire question. (P2 §1; dashboard-mobile.md.)

## Nits

1. **major · messages · row checkbox** — ~20px visual target (messages brief) under WCAG 2.5.8's 24px minimum; verify the hit area meets it (spacing exception aside). Source: P2 §7 / WCAG 2.2. Fix: pad the tap region to ≥24px (44px practical) without changing the visual.
2. **major · viewer · "MOVED TO CANVAS" badge** — the move is announced where its Undo isn't; undo lives only on the dashboard's Recent filings. Source: P1 §2 (global undo); dashboard brief ("Undo puts one back…"). Fix: Undo button on the badge / a viewer action row.
3. **minor · messages · repeated senders** — "notifications@instructure.com · Recent Canvas Notifications" repeats as separate rows (×2 visible); THE BAR asks high-volume senders to collapse to one row (HEY/Shortwave bundles). Source: P1 §1. Fix: fold same-sender runs into a bundle row with a count.
4. **minor · dashboard · "LLM classified 3,590 · 100% of 3,607"** — 99.5% rounds up to a hard "100%"; denominator unexplained. Source: honest-state principle (dashboard-mobile.md); P2 §1 anti-patterns. Fix: show "99%+" or state the 17-message remainder.
5. **minor · rules · row controls** — move-to-top / up / down + toggle + ellipsis crammed into one row; arrow targets look small (verify vs 44px practical). Source: WCAG 2.5.8 / P2 §7; Outlook up/down precedent P2 §2. Fix: enlarge targets or move "move to top" into the ellipsis menu.
6. **minor · viewer · audit trail** — only the move badge; no per-message history (which rule/flow touched it, when) though the viewer is billed as "message + action/audit trail" (page notes). Source: P1 §5 (log actions, keep undo reachable). Fix: tap the badge → small history popover.
7. **minor · settings · save feedback unverified** — "Save general" present, but a still can't show the announced status message the bar requires. Source: P2 §5 THE BAR; WCAG 4.1.3. Fix: verify/emit an announced "Saved" status on save.
8. **minor · log · filtering** — level chips + search + Pause are there, but no time-window filter (Vercel offers hour / 3 days / custom); verify the chip set covers Warning/Info rather than one cut-off "Er…". Source: P2 §3 THE BAR. Fix: add a time-window chip group.
9. **nit · messages · filter chip strip** — 4th chip cut mid-word with no fade/scroll cue (strips do scroll per brief). Source: P2 §8 (states/micro-detail craft). Fix: edge fade or peek-sized chips.
10. **nit · dashboard · status chip grid** — "Settings →" navigation sits as the 4th chip beside three boolean statuses (deliberate per brief, but mixes status and navigation). Source: P2 §1 (single-topic groupings; status names state + action). Fix: give "change" its own row or a plain link.
11. **nit · settings · sub-nav tabs** — 4th tab cut mid-word ("Clas…") with no scroll cue (verify it scrolls). Source: P2 §8. Fix: edge fade or shorter labels.
12. **nit · messages · "Learn rules (0)"** — disabled with no reason given; the empty-state bar wants reason + action. Source: P1 §8. Fix: inline "nothing to learn yet" hint or hide until ≥1 candidate.

---

**Summary**

- Strongest: rules, log, more — dry-run before commit, pausable live log, a long-tail hub that matches HIG; these are benchmark-grade surfaces.
- Weakest: viewer and messages — the triage loop breaks where it matters: the reader can't act or undo, the list can't gesture, read state doesn't show.
- Highest-leverage fix: make the viewer a triage surface (reply / archive / advance / undo at the badge), then mirror it with configurable row gestures.
- Trust items to close: dashboard-green vs same-day log-ERRORs, and proof of the assistant's confirm+undo gate (both "verify").
- Solid bones: 4 scoping axes, honest pagination, freshness + Check now, text-labeled statuses and severities, non-destructive toggles.
