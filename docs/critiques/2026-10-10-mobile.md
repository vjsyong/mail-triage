## Top gaps vs the commercial bar

1. **The messages fold is control chrome, not mail.** First row at y≈412 of 852 (measured); search card + filters toggle + chip row + full-width "Classify all (5)" before any message; ~3.2 rows of ~118px visible. Best: Superhuman and Spark — the list owns the canvas, search is one tap away (B1 §1). Why it matters for triage: a phone session is "scan the top of the queue"; every control above the fold taxes every visit. Fix: collapse search to a one-line trigger, move "Classify all" into selection mode (or below the list), target ≥6 rows.
2. **Failures still don't tell a story, and the numbers now disagree.** Re-verified live: the error path logs raw Python reprs ("act failed ({'op': 'move', …}): abort('command: UID => Connection is closed. 13')"), one failure produces two ERROR rows (rule layer at engine.py:1761 + act layer at engine.py:3162), and the dashboard's "8 errors" (8 messages in the errors filter) is a different number from the log's "Errors 6" (error log lines) for the same word. Best: Zapier's per-run history (in/out + explanation) [15] and Vercel's structured logs [16]. Why: auto-filing is the core promise; a failure needs "what happened + one action" on one row, and one number.
3. **The row support line is machine output, not mail.** Neither the messages list nor the dashboard's Recent mail shows the message's own snippet — the second line is the LLM summary and only appears once classified (app.py:6348, 2663); NEW/unclassified rows are sender + subject only. Best: Gmail (and Superhuman, Spark) — sender + subject + snippet + time is the row (B1 §1). Why: the snippet is what lets you decide without opening; an LLM one-liner is a second opinion, not a substitute. Fix: fall back to the stored snippet when no LLM summary exists.
4. **The reading pane spends fold 1 on triage chrome.** Subject, buttons, "Replies · draft and review", the moved banner and the correction form all sit above the body; the machine's own verdict is out of the first fold. Best: Gmail — the message is the message, actions compress to icon rows (B1 §3). Why: the viewer is where you *read*; making the body the last thing on screen inverts the hierarchy. Fix: body first, correction behind a "Fix category" disclosure.
5. **No reply-queue mode.** "Needs reply 10" is a filter; nothing in the captures runs a HEY-style Focus & Reply sequence that clears replies one after another in place (B1 §3 bar). Hedge: the collapsed "Replies · draft and review" panel could hide part of this — unverified, flagged not failed. Best: HEY (B1 §3). Why: the needs-reply set is the app's core work queue; draining it in one continuous mode is the highest-leverage loop. Fix: launch a focus mode from the "Needs reply" chip.
