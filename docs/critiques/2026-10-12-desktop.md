## Top gaps vs the commercial bar

1. **persisting — there is still no keyboard or command surface on desktop.** Re-verified today: the only keydown handlers in `app.py` remain Escape (1236, 1263), Enter-to-submit (1485) and the rail-resize grip (1967), plus the plugin SDK widget's Enter/Space (4558) — not triage bindings. Best: Fastmail's single-key model (`j`/`k`, `x`, `d`, `y`, `[`/`]`, `z` = undo last 10) and Superhuman's Cmd+K, "your master control for any action" (P1 §2, bar = ≥5 single-key actions). Why it matters for a triage app: at 1440px, triage speed *is* keyboard speed; mouse-only is the largest remaining distance between this and the products it borrows its look from.
2. **persisting — snooze cannot express the one intent people actually have.** Presets are still fixed durations, 24 / 72 / 168 hours, in both the workbench (6702) and the rail (6831–6833), with no clock anchor and no "this afternoon/tonight". Best: Gmail/Spark clock-anchored presets, Shortwave's AI-suggested times (P1 §2). Why it matters: "1 day" returns mail at an arbitrary hour; the needs-reply queue is exactly where "tomorrow 9am" does its work.
3. **persisting — search still cannot become a rule or a saved view.** The messages surface offers Search + "More filters" (Sender / Category / Folder) and the rules page offers only "New rule"; nothing takes a search that just returned 37 pages of noise and turns it into a rule or a filter chip. Best: Fastmail (any search result becomes a rule) and Gmail (build a filter from criteria, test the search first), plus Shortwave's custom-query Splits (P1 §1, P2 §2, [11][12]). Why it matters: this is the loop that makes a triage app quieter over time.
4. **persisting — undo lives a page away from the mutation.** Machine-filing undo is real (dashboard "Recent filings" card with an Undo button) but reachable only from the dashboard; the viewer's audit trail is collapsed by default (here: "Audit trail · 0 events"), and classifier/rule toggles and category corrections carry no undo at all. Best: Gemini gates agentic actions with confirm plus a 60s undo right where you confirmed (P1 §5 (c)/(d), "60s floor"). Why it matters: if reversal requires finding the change elsewhere, every approval gets heavier.
5. **persisting — deterministic fast-paths still carry no dry-run scorecard, while rules have two.** Classifiers run *before* the LLM, both are ON and WEAK-labelled, and their controls are Dataset / toggle / ⋯ (Retrain, Delete…) — there is no "test against the last 200 messages" for a heuristic, though the rules page has exactly that affordance. Best: Gmail (verify matches with Search before committing) and Outlook ("Run this new rule now on messages already in the current folder") — P2 §2, [11][13]. Why it matters: enabling one changes filings silently and bypasses the model everything else is validated against; the user cannot see the blast radius.

## Nits

1. **major — messages — the "Needs reply 10" queue has no row-level mark.** TAG and SNOOZED states render on rows (6355–6356) and the viewer badges needs-reply (6684), but the list — the surface whose filter row advertises 10 such messages — never says which rows they are. Source: P1 §1 row anatomy (a row should say what it wants), P1 §3 (linear "needs reply" queue). Fix: render the existing `llm_needs_reply` flag as a small badge in the status/tag cell.
2. **minor — messages — no freshness or refresh in the busiest header.** The list header offers Search/filters only; freshness lives in the sidebar's global "checks every 90s / Last check 1m ago", and "Check now" exists on the dashboard but not here. Source: P1 §6 THE BAR (visible freshness + manual refresh; Fastmail's `u`). Fix: reuse the dashboard's "Check now" + "Last check" in the messages toolbar.
3. **minor — messages — one snippet still opens with tracker boilerplate.** Row 4's preview is "If you can't read this email, click here <https://hkust.edu.hk/news/…>". Source: P1 §1 (the snippet earns its line). Fix: strip quoted/boilerplate lines and bare URLs before clipping. (Persisting from 10-11; re-verified today.)
4. **minor — messages — the CATEGORY column answers only for LLM-filed mail.** The cell renders `m.llm` (6357), so the rule-filed rows that make up "Sorted 2608" show a badge but no destination, and the list cannot answer "where did it go" for them. Source: P1 §8 ("why is this here / where did it go"), P2 §1. Fix: fill the cell from the rule action's destination (the rules page already renders "move → Newsletters").
5. **minor — dashboard — the attention panel is untimestamped.** "10 need a reply" / "9 failed messages" as of when? Source: P2 §1 (untimestamped "recent" data anti-pattern). Fix: an "as of HH:MM" line on the card.
6. **minor — viewer — snooze and needs-reply render twice with two vocabularies.** Workbench "Snooze" `<details>` + "Needs reply" button (6702–6703) vs rail "Needs reply: not flagged" + "1 day / 3 days / 1 week" buttons (6814, 6831–6833). Source: P2 §8 (states and micro-details deliberate). Fix: one canonical control, the other a state mirror.
7. **minor — viewer — no Reply-all or Forward.** Grepped today: no such control in the templates; the workbench offers "Draft reply" alone. Source: P1 §3 bar (reply / reply-all / forward). Fix: expose both in the workbench.
8. **minor — rules — no per-rule fire history.** You can dry-run the whole list but cannot see whether rule #6 has ever fired, or when. Source: P2 §2 (Zapier's Zap History logs every run, [15]). Fix: last-fired + match-count column per rule.
9. **minor — classifiers — "1 removed" is dateless and reasonless.** The sample-exclusion badge prints a count only (3484). Source: P2 §1 (untimestamped data). Fix: hover/expand with date + reason.
10. **nit — settings — Remote Images is a checkbox where the app's control language is the switch.** Classifier rows and proxy/filing toggles use the blue switch; this one setting breaks the pattern. Source: P2 §8. Fix: use the same switch component.
11. **nit — accounts — no per-account check, and the proxy explainer is prose-only.** The card states READING / AUTHORISED + token expiry but offers no "Check now" of its own (freshness is the sidebar's global line), and "How the proxy works (click to read)" lacks the ▶ affordance "Setup details" uses. Source: P2 §1 (state + next action) / P1 §6 (visible freshness + manual refresh). Fix: per-account "Check now"; make the explainer a disclosure.
12. **nit — assistant — duplicate truncated titles survive, so saved chats collide.** "Find me messages…" at 10-05 20:50 and 10-05 19:29 are indistinguishable; "What rules would you…" has a near-twin (zoom-verified today). Source: P2 §8. Fix: show the full title on the row plus HH:MM, or disambiguate with the first message.
