## Top gaps vs the commercial bar

1. **Errors have an address but no recovery loop at that address.** The dashboard counts "7 errors" and links to the filtered list (2487); red ERROR badges sit on rows in the messages page; but the reversal control — "Retry parked" (`retry_errors`, 2562) — renders inside the systems card two cards below (below the fold), and per-message recovery is "Re-classify with LLM" inside the viewer. Best: Zapier replays failed runs from the run history you are already in, with Data-in/Data-out per run [P2 §2, refs 15]; Vercel lets you drill from a failing status in the log view [ref 16]. Why it matters for a triage app: an ERROR row is un-triaged mail; a debt counter whose fix lives on another page trains the operator to ignore it. Fix: a per-row retry and a "retry all failed" on the Errors view itself.
2. **The needs-reply queue never pushes back.** "5 need a reply" is the hero stat and a filter chip, with a per-message flag and manual snooze (1/3/7 days, "hide it from the lists", 6818) — but nothing in the eight screens ages, nudges, or resurfaces mail you haven't answered, and the UI source contains no reminder/resurface strings (repo grep "remind|resurface" — none). Best: Superhuman Auto Reminders resurface unanswered mail after 1–7 days [P1 §2]; HEY Bubble Up returns an item to the top later [P1 §2]. Why it matters: need-a-reply is the app's core promise; a queue that never escalates becomes wallpaper and the user re-derives urgency from memory every morning.
3. **Undo sits a page away from the approval.** Approvals are the mutation gate (dashboard counter 2488; assistant "Awaiting your approval" card 7629), but no undo appears on any assistant or approval surface in today's shots; the app's machine-move undo ("Undo puts one back and keeps automation off it") lives only on the dashboard's Recent filings card below the fold (2631-2641). Best: Gemini gates agentic actions with confirm + a 60s undo after confirming [P1 §5]. Why it matters: approve-then-regret is the one risk of an agentic mailbox; if reversal means finding the filing on another page, users over-verify before approving and the automation's speed is wasted.
4. **No path from a search to a rule or a saved view (persists from 2026-10-08, re-verified).** Today's search card is Search + "More filters" only — no save-as-rule; a repo grep finds no such affordance. Best: Fastmail — any search result can become a rule [P2 §2, ref 12]; Gmail — build a filter from search criteria and test the search before committing [ref 11]; Shortwave ships custom-query Splits [P1 §1]. Why it matters: it breaks the one loop that makes a triage app get quieter over time — "I keep seeing this pattern → encode it once" — exactly when the evidence is on screen.
5. **Classifier trust is asserted, not shown.** Both fast-paths carry a WEAK provenance badge; the Newsletter row shows an untimed "1 REMOVED"; the only quality numbers are settings ("min conf 0.80"), not evidence. A fast-path classifier files mail *without* an LLM review — the one automation that most needs a demonstrated accuracy/coverage number (and a last-eval date) next to the badge. Best: Zapier's Test tab shows Data in / Data out per step and every run is logged in History [P2 §2, refs 15]; Gmail makes you test the matched set before committing a filter [ref 11]. (If the Dataset page carries eval numbers, the list page doesn't say so.) Fix direction: a last-eval "accuracy × coverage" chip beside WEAK, linking to the dataset.

## Summary

- 8 screens: 2 better than the peer bar (rules, accounts), 5 par (dashboard, viewer, assistant, settings, classifiers), 1 worse (messages).
- The app stays strongest at provenance — audit trails, verification, status wording — and weakest at the triage loop's three ends: recovery (errors), resurfacing (need reply), reversal (undo at approval).
- Fresh gaps: error-recovery co-location, reply-queue nudges, undo-at-approval; persisting gap re-verified: search→rule pipeline (no save-as-rule anywhere).
