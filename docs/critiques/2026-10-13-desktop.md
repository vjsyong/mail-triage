# Desktop critique — 2026-10-13 (1440x900)

Yardstick: `docs/ux-benchmarks.md` in full (Part 1 = email-product bars S1–S8; Part 2 = craft bars
S1–S8, cited as P1-Sn / P2-Sn) plus `docs/ui-redesign.md` (the repo's design brief, cited as
brief §pass). Screens: dashboard, messages, viewer, assistant, rules, settings, classifiers,
accounts. Invariants not flagged: square corners, light Vercel theme, Geist, black log panels,
blue links. Screenshots are static, so anything about hover states, confirm dialogs, motion or
ARIA is marked as unverifiable rather than counted.

## Verdicts

- **dashboard — par vs Vercel's status conventions + Pencil&Paper/M3 KPI rules (P2-S1)** — the
  hero answers one question ("13 need a reply") with an exception pair (red "10 failed messages")
  and status chips that name a state in words, not colour alone; it loses on freshness — status
  chips and the Recent mail card carry no "verified as of" context (P2-S1 bar: status card names
  state + action; timestamps on "recent" data).
- **messages — better vs Gmail's web list (P1-S1)** — seven counted scope axes ("All 3702 /
  Errors / Awaiting LLM / Needs reply / Sorted / Tagged / Snoozed"), select-all with totals,
  honest "3702 messages · page 1 of 38", and a scoped bulk verb ("Classify all unclassified (6)")
  beat the "≥2 scoping axes" bar; it loses on row identity (nit 1) and grouping (gap 2).
- **viewer — better vs Gmail's reading pane (P1-S3), par vs HEY** — header-first meta with a
  pretty date and tz ("Tue 13 Oct 2026 · 09:26 UTC+8"), Newer/Older, an inline "LLM summary: … ·
  why: … · filed to Newsletters", a correction control that says "Teaches the models; does not
  move mail.", and a visible "← Messages" back control (P1-S3, P2-S6); it loses on duplicate
  controls and preset depth (nits 3–4).
- **assistant — par vs Gmail Gemini's sidebar assistant (P1-S5)** — history rail with resumable
  sessions, an empty state that is title + reason + five starter chips (beats P1-S8's "one
  action"), Enter-to-send stated, honest "Model: mimo-v2.6-9b"; P1-S5's bars (c) confirm + undo
  and (b) visible tool actions are claimed in copy ("proposes rules you approve with one click")
  but not verifiable from an empty transcript.
- **rules — better vs Outlook's rule manager (P2-S2)** — ordered list, the evaluation model
  taught in the page copy ("Evaluated top to bottom — first match wins… A rule with no actions is
  a guard"), per-rule toggle present alongside Edit/Delete, and a page-level dry run ("Test
  against last 200 messages") that Outlook only offers as "run now on existing messages"; it
  loses on reorder ergonomics (nit 8).
- **settings — par vs Apple HIG's settings split (P2-S5, P1-S7)** — five task-named sections,
  scoped per-card saves ("Save general"), every control shows its current value with a one-line
  helper ("Time display offset (hours) … timestamps show as UTC+8"); it loses the shortcut
  reference P1-S7 asks for, and the status group the brief named is demoted to a disclosure.
- **classifiers — par vs Superhuman AI Categorization / Shortwave AI filters (P1-S1, P1-S5)** —
  neither peer exposes the model; this page shows kind, samples (with "1 REMOVED"), label
  provenance, the decision rules, and an updated date, which is real transparency the commercial
  bar doesn't reach; it loses on vocabulary (nit 10).
- **accounts — better vs the connected-account status patterns the brief cites (brief §2nd pass)**
  — status-driven primary action ("Re-authorise"), READING / AUTHORISED / PROXY RUNNING badges,
  proxy strip with live endpoint ("127.0.0.1:1993 · running since 10-12 10:49") plus Restart /
  Proxy log, and "Setup details" tucked behind a disclosure; it loses on per-account freshness
  (nit 12).

## Top gaps vs the commercial bar

1. **No keyboard-first layer anywhere on the desktop.** Superhuman's bar is Cmd/Ctrl+K as "your
   master control for any action" with every shortcut listed beside it, and Fastmail ships ≥5
   single-key actions plus a 10-action undo stack (P1-S2; the P1-S7 bar also asks for a shortcut
   reference). We show zero shortcut affordance on any of the eight screens — no palette, no
   hover hints, nothing in Settings. For an app whose thesis is triage speed, and on the desktop
   viewport specifically, that's the biggest single miss.
2. **The list doesn't collapse threads or noisy senders.** Gmail threads by default, HEY collapses
   a dominating sender to one row, Shortwave bundles, Spark's Smart Inbox recedes the seen
   (P1-S1 bar: "high-volume senders collapse to one row"). In the captured page, six of eight
   visible rows are two conversations — four "RE: TLE_ Round 1 admission interview" and two
   `no-reply@zoom.us`. The queue looks ~2.5× longer than it is, and the user re-decides the same
   thread repeatedly.
3. **The app's own mutations have no visible escape hatch.** The viewer states outcomes
   ("MOVED TO NEWSLETTERS", "LLM: NEWSLETTER (95%)") but nothing on any screen shows an undo for
   a file/snooze/tag, and rules Delete sits one click away. The bar is explicit: global undo
   (toast or ~10-action stack), destructive actions confirmed or undoable, and agentic mutations
   gated by confirm + undo with a 60s floor (P1-S2, P1-S5(c); Gmail Gemini 60s undo, Fastmail 10
   actions). Trust in an auto-filing mail app is built exactly here.
4. **"Needs reply 13" is a filter, not a working mode.** HEY gives Reply Later its own pile and
   Focus & Reply that shows *only* that mail and clears items one after another; Gmail has
   auto-advance (P1-S2, P1-S3). We have a chip and a viewer with Newer/Older, so the user must
   bounce back to the list (or re-filter) after each reply. The hero metric on the dashboard
   deserves a first-class queue.
5. **Bulk triage exposes exactly one verb.** The list has always-visible checkboxes, select-all
   and totals (good — brief §tables), but the only bulk action visible is "Classify all unclassified
   (6)". Gmail/Spark let selection carry the triage actions, and the P1-S2 bar includes range bulk
   select. With 3,702 messages and 38 pages, classify-only bulk is the wrong bottleneck: file,
   tag, snooze and needs-reply are the verbs a backlog actually needs, and the app already knows
   how to do all of them.

## Nits

1. **major — messages — no untouched/read signal.** P1-S1's bar is "row = sender + subject +
   snippet + time + **unmistakable unread affordance**". The table carries DATE / FROM / SUBJECT /
   STATUS / CATEGORY and nothing that says "you have not looked at this" (STATUS covers machine
   states; the soft recession is status-derived by design and not re-filed here). *Fix:* a
   text-backed "New" marker or a 3px left rail on the untouched state only — never colour alone
   (P2-S7, 1.4.11).
2. **minor — messages — internal vocabulary in the filter chips.** "Sorted 2619" and "Awaiting
   LLM 6" are the app's words; HEY and Spark name their piles in user language (Paper Trail,
   Seen) and P1-S1's bar treats the list as a triage surface for humans. *Fix:* rename to the
   outcome ("Filed 2619", "Not yet classified 6").
3. **minor — viewer — "Needs reply" appears twice.** It is a top action cluster button *and* a
   rail row ("Needs reply: not flagged"). HIG/M3 and the P1-S7 bar both say don't duplicate a
   control on one surface; two copies of one state also disagree in tone (button vs status).
   *Fix:* keep the rail as the status readout and make the top one a toggle that reflects it.
4. **minor — viewer — snooze presets are too coarse.** Only 1 day / 3 days / 1 week, where the
   P1-S2 bar asks for today / tomorrow / weekend / next week / custom (Fastmail's `b`+1–7, Spark's
   configurable times). *Fix:* add "Tomorrow 09:00" and a date field.
5. **minor — all screens — the same LLM fact is rendered as three different chips.** Green
   "LLM → FOLDER" (list, dashboard), blue "CLASSIFIED" (list), blue "LLM: NEWSLETTER (95%)"
   (viewer), grey "MOVED TO NEWSLETTERS" (viewer). P2-S3/P2-S8 want colour to mean one thing, and
   the craft bar says a default the design system wouldn't ship is a finding. *Fix:* one chip
   component with a fixed colour→meaning map (machine-filed / machine-classified / user-moved).
6. **minor — dashboard — "Recent mail" has no freshness line.** Rows have times; the card does
   not say when the list was last refreshed, and P2-S1 explicitly bars untimestamped "recent"
   data. (The sidebar's "Last check 1m ago" is global chrome, not card context.) *Fix:* "as of
   09:31 · last check 1m ago" in the card header.
7. **minor — dashboard — status chips name a state but no verification time or action.** "Rules
   live", "LLM on", "Auto-filing ON" — P2-S1's bar is "state + next action", and brief §4th pass
   specified a system strip for Triage / Proxy / Index / LLM with live detail; the shipped strip
   shows three chips and drops Proxy and Index (which now live only on Accounts). *Fix:* add the
   verifying timestamp per chip and link each chip to the surface that owns it.
8. **minor — rules — two visually identical ↑ glyphs with different effects.** Row controls show
   up-one and move-to-top as adjacent same-sized arrows next to ↓, with no labels; the P2-S2
   reorder bar looks to Zapier's labelled drag handle, and P2-S7/WCAG 2.2 wants ≥24px targets and
   unambiguous affordances. *Fix:* label the jump ("Top") or adopt the drag handle.
9. **minor — classifiers — raw internal vocabulary.** KIND reads "decision_list", the subtitle
   reads "min conf 0.80 · by demo", and the label badge reads "WEAK" with no on-screen legend.
   P1-S7/P2-S8 want task-named, user-language surfaces. *Fix:* "Type: decision list (rule-based)",
   "trained from demo mail", and a tooltip explaining weak labels.
10. **minor — classifiers — the MATCHES ON cell is a dense one-line dump.** Each row renders
    several full rules with `(100%, n=95)` suffixes and truncates mid-rule with an ellipsis.
    *Fix:* show the top 3 with "…N more" behind a per-row disclosure.
11. **minor — accounts — token expiry with no consequence stated.** "access token until 10-13
    11:22" gives a deadline without saying whether it renews silently or whether the user must act
    — P2-S1: state + next action. *Fix:* "renews automatically" or "Re-authorise after 11:22".
12. **minor — accounts — no per-account freshness.** The card shows token expiry, not when mail
    was last read; P1-S6's bar wants visible sync/freshness state (synced / syncing / offline) plus
    a manual refresh, and the sidebar's "Last check 1m ago" is account-agnostic. *Fix:* "last read
    1m ago · Check now" on the card.

No blockers found: every page renders cleanly at 1440x900, no overflow, no clipped table, and the
2026-10-06 contrast pass (brief §Contrast) is not contradicted by anything visible here.

Not assessed from static shots (state explicitly, not scored): focus rings, hover/pressed states,
toasts and status announcements (4.1.3), reduced motion and transition timing, keyboard operability
and DOM semantics, contrast ratios measured on the shipped pixels, empty states for filters that
currently have rows, and the phone-first surfaces (bottom nav, 320px reflow — those are the mobile
critique's remit).

## Summary

The desktop set clears the commercial bar on information design: counted filters, an inline LLM
verdict with its "why", guard semantics in the rules list, status-driven account actions.
What is missing is a layer, not a screen — no keyboard model, no thread/sender collapsing, and no
visible undo for the app's own mutations: exactly what makes Superhuman, Fastmail, Gmail and HEY
feel fast and safe. Fix order: undo beside every machine move, then list grouping, then commands.
Twelve nits, none a blocker; the shared-chip inconsistency (nit 5) is the cheapest real win.
