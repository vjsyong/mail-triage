## Verdicts — one line per screen

- **dashboard — par vs Vercel's status/stat conventions (P2 §1; Pencil&Paper via [23])** — bar: hero stat answers one question and links to the filtered list; status card names state + next action; timestamps on "recent" data. We: hero counts each link to their exact filtered list (app.py:2484-2488), chips are label + dot, not colour-alone (.dschip:2391-2393), parked errors get state + action ("Retry parked", 2558-2561), filings carry one-tap Undo with a keep guard (2628-2640; undo brief). Drag: `1 errors` is ungrammatical (hardcoded plural, 2486); the "hero" bundles three different questions into one card.
- **messages — worse vs the Gmail list-and-triage / Fastmail keyboard bar (P1 §1-2)** — bar: threads grouped by default, sender collapse, unmistakable unread affordance, ≥5 single-key actions, range select, global undo. We: row anatomy, scoping and bulk pass (7 filter chips + sender/category/folder/date search, 6293-6305, 6446-6449; bulk tag/classify with live count, 6323-6333; empty state title+reason+action, 6355-6360), but flat rows (no threading, 6341-6351), no read/unread state (the app's own brief lists "per-message read state" as open), no per-row actions (`.rowacts` exists on rules/classifiers/templates but not here), no keyboard.
- **viewer — par vs Fastmail/Shortwave reading pane (P1 §3)** — bar: next/prev + archive-and-advance + reply/reply-all/forward; pane carries its own actions. We: `← Newer / Older →` + `File & next` + `No reply needed & next`, all scoped to the incoming filter (6682-6688); queue work survives triage. Ahead of Gmail's defaults on verification: reply-status panel with "Check sent replies" (6707-6712) and a per-message audit trail "oldest first" (6754-6756) — the P1 §5(d) "never silently modify mail — log actions" bar, met. Behind: no reply-all/forward; compose is draft-to-Drafts only by design (6696-6705), so there is no send and no undo-send moment at all.
- **assistant — par vs Shortwave/Gemini (P1 §5)** — bar: chat that acts across the mailbox with visible actions; every mutation gated by confirm + undo; inline summarize + draft on the open message. We: gated proposals ("Awaiting your approval", Approve/Dismiss, "Nothing happens until you click", 7624-7641), an always-visible permission disclosure ("Can do directly / Asks first / Off", 7656-7664), session rail with title tooltips (7604) — ahead of HEY/Spark/Apple/Fastmail, which ship no AI (P1 §5). Can't verify live step streaming from a still (copy claims it, 7589). The inline half of the bar lives in the viewer, not here — see gap 5.
- **rules — better vs Gmail filters / Outlook rules (P2 §2)** — bar: ordered editable conditions+actions, non-destructive toggle, dry-run before commit, guarded reordering. We: "Evaluated top to bottom — first match wins" + guards teach the model (2888); per-rule toggle, pin/up/down reorder (2919-2926); dry-run via "Test against last 200 messages" and "Simulate a draft" (2892-2893) — the Gmail "test the search before committing" affordance, plus Outlook's up/down ordering model; does not need drag-to-reorder (Zapier's drag is the alternative, not the bar).
- **settings — par vs Gmail/Spark settings organization (P1 §7; HIG via P2 §5)** — bar: task-named sections, current values visible, scope stated, triage actions stay in the main flow. We: General/AI/Mail/Automation/Search nav (sticky, 8856), label+helper+current value per row ("Sean", "8", "Always load", 8899-8902), disclosure "Advanced · effective system status", scope footnote. One real wart: "Time display offset (hours)" is an implementation-flavoured number input where users think in zones/cities (8900-8901) — self-documenting via the helper, so minor.
- **classifiers — par vs the rule/classifier-editor bar (P2 §2)** — bar: ordered editable conditions; dry-run before commit; provenance clear. We: non-destructive toggles, per-classifier Dataset review (sample-level dry-run), retrain/delete behind a ⋯ menu with a two-press "Press again to delete" arm (3492-3499), and a WEAK provenance badge when training labels are LLM auto-tags (3484) — genuine provenance craft the commercial peers don't show. Wart: the "matches on" decision list is hard-clipped with no way to see the rest (see nits).
- **accounts — better vs the status-surface bar (P2 §1; Vercel conventions via [16])** — bar: state + next action, not just a colour. We: proxy card states RUNNING + address + pid + uptime with "Restart proxy" beside it (9738); the account card carries READING/AUTHORISED badges, token expiry, and names its recovery action "Re-authorise" as the primary button (9758). Complete for its scope.

## Top gaps vs the commercial bar

1. **No keyboard model — no shortcuts, no command palette.** Superhuman's Cmd+K is "your master control for any action", each action's shortcut listed beside it; Fastmail runs j/k/x/d/y/[/] with `z` undoing the last 10 actions (P1 §2). We: no list or triage bindings and no palette — the app's only keydown handlers are Escape (disarm/close), Enter-to-submit in the two composers, and arrow keys on the assistant side-panel resize grip (app.py:1235, 1484, 1966, 4557) — every triage action is a mouse trip, even though the queue mechanics ("File & next") are built for keyboard. Why it matters: at 1440px the triager expects to process mail without leaving the home row; the app's own brief still lists "keyboard j/k bindings" as open. Best: Superhuman (palette) + Fastmail (bindings).
2. **The list doesn't triage — no threading, no sender collapse, no read state, no row actions.** Gmail groups threads by default; HEY collapses a dominating sender to one row and moves transactional mail out; Spark drops read mail into a "Seen" section (P1 §1). We: one row per message, one sender can occupy a row per mail (calendar@ust.hk twice on the dashboard fold; the same daily alert repeats in the list), and the row anatomy bar's "unmistakable unread affordance" has no equivalent. Why it matters: the scan cost is the product's core cost; grouping/sinking is how the leaders cut it. Best: Gmail (threads) / HEY (sender collapse).
3. **Undo stops where the app starts doing things.** Gmail ships a 30s undo toast; Fastmail `z` undoes up to 10 actions; the bar is "global undo (toast or ~10-action stack)" (P1 §2). We: undo exists for machine/user *moves* only — all six move sites + a keep guard (undo brief §§undo/keep) — while tag, untag, needs-reply clearing, snooze and category corrections are fire-and-forget; deletes use two-press arming instead. Why it matters: triage speed is inversely proportional to fear of irreversible actions. Best: Fastmail (z-stack).
4. **Compose is one verb, saved manually.** Bar wants reply/reply-all/forward plus "drafts autosave visibly" ending in an editable draft (P1 §3-4). We: `Draft reply` → template select → LLM draft → manual "Save to Drafts" (6696-6705); no reply-all, no forward, no autosave, and (by design, stated in the UI) nothing can be sent. Honest read: send/undo-send is deliberately out of scope — mail sends from the user's client — but reply-all/forward cost nothing to draft and their absence forces a context switch to Outlook, which the app otherwise works hard to avoid. Best: Gmail/Fastmail/Spark compose set.
5. **AI is chat-first; the open message gets answers, not actions.** Gmail Gemini puts Summarize/Draft/Add-to-calendar inline above the thread with hover-previewable smart replies; Shortwave works on "any email on your screen" with an inline Improve-draft button (P1 §3, §5). We: the viewer's inline AI is a stored classification summary + correction widget (6723-6724) — read-only context; drafting is a separate form with a template dropdown. Why it matters: triage lives on the open message; that is where AI saves the most seconds per action. Best: Gmail Gemini (inline set) / Shortwave (inline draft).

## Nits

1. **minor — dashboard — "Needs your attention": `1 errors`.** Hardcoded plural: `<b>{{ st.errors }}</b> errors` (app.py:2486) renders "1 errors" for one parked message. Source: grammar / P2 §1 status-card text quality. Fix: `{{ 'error' if st.errors == 1 else 'errors' }}`.
2. **minor — messages — no read/unread affordance on rows.** The row template has date/from/subject/tag/status/category and no read state (6341-6351); P1 §1 THE BAR asks for "unmistakable unread affordance", and undo-triage-snooze.md already lists read state as open. Fix: bold sender + a 6px dot for unseen mail.
3. **minor — classifiers — "matches on" is hard-clipped at 170 chars with no tooltip.** `{{ h.description[:170] }}` (3485) — screenshot cuts mid-word ("…departmen"). Everywhere else the app pairs `clip()` with a `title=` (e.g. mail rows 6345-6347); P2 §2 expects the editor to show the conditions. Fix: add `title` or an expandable details.
4. **minor — classifiers — "-1 REMOVED" reads as a negative quantity.** Source renders `-{{ h.excluded }} removed` (3483) for 1 excluded sample. Fix: drop the minus ("1 removed").
5. **minor — viewer — snooze presets are only 1 day / 3 days / 1 week** (6693, 6821-6823); P1 §2 bar wants today/tomorrow/weekend/next-week/custom presets (Fastmail `b`+1-7). Fix: add "Tomorrow 8am" and "Weekend" (and custom) presets.
6. **minor — viewer — the reply draft has no autosave; only a manual "Save to Drafts".** P1 §4 bar: "drafts autosave visibly". A typed draft lost to a navigation is the classic triage appdata loss. Fix: autosave the textarea (local) with a visible "saved" state.
7. **minor — assistant — deleting a saved chat is one unguarded click.** The rail row's ✕ posts immediately (7606); P1 §2 bar: "destructive actions confirmed or undoable", and the app itself arms destructive deletes elsewhere ("Press again to delete", 3497). Fix: use the same arm pattern or an undo toast.
8. **nit — assistant — the empty state shows six chips with a near-duplicate pair** ("Find an old invoice" 7772 and plugin chip "Find invoices" 7893). assistant-page.md's own decision was "four chips, no marketing"; the research it quotes says 3-4. Fix: merge/drop one.
9. **minor — messages — bulk select can't reach beyond the current page.** `#selall` toggles only the checkboxes rendered on this page (6337, 6387); P1 §2 bar counts "range bulk select" (Fastmail x/Shift+x). With 3,629 messages / 37 pages, "classify all matching" means paging. Fix: shift-click range + a "select all N matching this filter" affordance.
10. **nit — dashboard — /messages is offered twice above the fold** ("Open messages" button, 2623; "All messages →" in the Recent mail header). One is enough; keep the card link, drop the button (or vice versa). Source: P2 §1 card-as-entry-point.
11. **nit — accounts — "(click to read)" under the "How the proxy works" summary** (9818) is redundant copy on a native `<details>` (the summary *is* the control). Fix: drop the parenthetical.

## Summary

- Three surfaces beat or meet the bar outright: accounts, rules, and the viewer's triage mechanics (queue + reply check + audit trail).
- The desktop story is weakest where the keyboard and the list are concerned: no shortcuts/palette, no threading, no read state, no row actions, no universal undo.
- Two unforced copy/craft defects: "1 errors" (2486) and the clipped classifier conditions (3485).
- One designed limitation is honestly labelled: compose drafts to Drafts and cannot send — that also explains the missing reply-all/forward.
- Biggest single-leverage fix: a keyboard layer over the existing filter-scoped queue (j/k + file/reply/snooze + undo).
- Contrast, focus rings, empty states, and destructive-action confirmation were checked and pass; no false alarms promoted from the screenshots.
