## Verdicts — one line per screen

- **dashboard — better vs the Vercel/Linear status-card bar (B2 §1 [23][26][16]).** Attention
  counts are the one thing this screen is for and they deep-link to their queues ("9 failed
  messages" → `f=errors`, app.py:2486-2487), freshness is always on, and today the count held at
  9 (2 → 7 → 8 → 9 → 9 across five captures). Watch items: the fourth tile in the "Needs your
  attention" grid is a Settings nav link sitting among three status tiles, and the red 9 still
  has no on-screen explanation of *what* the nine are.
- **messages — worse vs Superhuman / Spark / Gmail (B1 §1).** Search card, "More filters", the
  chip row and a full-width "Classify all (6)" all precede row 1 (app.py:6299-6323); the first
  row still lands around mid-screen and "3682 messages · page 1 of 37" sizes the screen as an
  archive. The row itself is commercial-grade now: sender + subject + the mail's own snippet +
  time + status badge, with processed rows correctly receding (`tr.r-dim`, app.py:6349).
- **viewer — par vs Gmail / Fastmail reading pane (B1 §3).** Honest state, one-tap Newer/Older,
  Draft reply / Snooze / Needs reply, and the machine's verdict disclosed as a badge rather than
  a blind write. Loses the point on fold order — correction form and collapsible reply panel
  still sit above the body (deferred item, unchanged) — and there is no archive-and-advance:
  "File & next" renders only when the LLM already suggested a folder (`can_file`, app.py:6689).
- **assistant — par vs Shortwave / Gemini (B1 §5).** Taught empty state ("Ask about your mail",
  five one-tap chips), model disclosed under "assistant details" ("Model: mimo-v2.6-9b"), Send
  row anchored above the tab bar. Chat substance is unjudgeable from a still — flagged, not
  failed. The header still drops the app's freshness signal (nit 6).
- **rules — better vs Outlook rules as experienced on a phone (B2 §2 [11][13][15]).** Ordered
  numbered cards, guard semantics ("keep in place (guard)"), mono conditions, both dry-runs
  ("Test against last 200 messages", "Simulate a draft") above the list, non-destructive toggles.
- **settings — par vs Gmail / Apple settings (B1 §7, B2 §5 [7]).** Five task-named tabs; every
  visible control shows a label, a description and its current value ("Sean", "8", "Always
  load"); the remote-images copy is now unambiguous. Residual: the save row has no dirty/saved
  state (nit 7).
- **more — par vs the HIG More-menu pattern (B2 §5 [7]).** Long-tail destinations only
  (Get started checklist, AUTOMATION, SYSTEM), each with a one-line description and a chevron;
  nothing duplicated from the tab bar.
- **log — worse on the error path, par on structure, vs Vercel Runtime Logs (B2 §3 [16]).**
  Structure meets the bar: newest-first, mono, severity as colour *and* text, scope line ("times
  in UTC+8 (debug lines hidden)"), level chips, search, live mode with Pause (`app.py:10280`,
  10s auto-refresh). But the ERROR row still ships Python internals verbatim and "Errors 1"
  refuses to reconcile with the dashboard's 9.

## Top gaps vs the commercial bar

1. **The messages fold is still control chrome, not mail.** A search card + "More filters" +
   chip row + full-width "Classify all (6)" are permanent furniture above the first row, and
   "page 1 of 37" announces an archive. Best: Superhuman and Spark — the list owns the canvas,
   search and bulk actions are one tap away, not standing chrome (B1 §1). Why it matters: a phone
   session is "scan the top of the queue"; every control above the fold taxes every visit. Fix:
   search behind a one-line trigger, "Classify all" moved into selection mode or below the list,
   target ≥6 rows in fold 1.
2. **Failures have no home and no story.** One red number on the dashboard (9 messages with
   `status='error'`, app.py:262), one chip on the log ("Errors 1" = error rows in the last 1000
   events, app.py:10339), one buried list filter — three surfaces sharing the word "error", none
   reconciling with the others, none showing "what happened → one action" for a single failure.
   Best: Zapier's per-run history (data in / data out / what failed) [15] and Vercel's
   structured logs [16]. Why it matters: auto-filing is this app's core promise, so a filing
   failure needs to be as triageable as a message. Fix: a failure row = message + rule +
   reason + Retry / Open.
3. **No reply-queue mode.** "Needs reply 10" is still only a filter. The single in-place clear,
   "No reply needed & next" (app.py:6697), is conditional on `m.llm_needs_reply` and lives inside
   the viewer; there is no counter, no progress and no entry from the chip that defines the
   queue. Best: HEY's Focus & Reply — shows only Reply Later mail and clears items one after
   another (B1 §2, §3). Why it matters: the needs-reply set is the app's core *human* queue, and
   draining it one push/pop per message is the highest-friction loop on a phone. Fix: launch a
   focus mode from the "Needs reply" chip.
4. **The row's decision text is the machine's words whenever a summary exists.** app.py:6354
   still renders `llm_summary` first and the mail's own snippet only as a fallback
   (`{% if m.llm_summary %}…{% elif m.snippet %}…`), unchanged since 10-11. Best: Gmail / Spark —
   the row is sender + subject + the message's snippet + time (B1 §1 THE BAR). Why it matters:
   the snippet is what lets you decide without opening; an LLM paraphrase is a second opinion,
   not a substitute. Fix: snippet always; summary as a secondary badge or tooltip.
5. **The list has no row-level actions.** No touch/pointer gesture handlers touch list rows
   anywhere in the app (the only `pointerdown` is the assistant panel grip, app.py:1948), so
   every action is open-message → act → back. Best: Gmail / Spark / Superhuman per-direction
   swipe including snooze and a None option (B1 §2), with WCAG's non-swipe path kept (B2 §7
   [3] — we have only the button path). Why it matters: on a phone, triage is thumb-level; a
   list where nothing can be done from the row costs a page push and pop per item. Fix: a row
   action sheet (long-press) or swipe for Snooze / Needs reply / No reply needed.

## Summary

- Verdicts: 2 better (dashboard, rules), 5 par (viewer, assistant, settings, more, log-structure),
  1 worse (messages), with log's error path called out as worse-on-content.
- Landed since 10-11: reconnect WARN lines are prose with retry counters; remote-images copy
  states both states; rules reorder glyphs read distinctly at full res.
- Top gap unchanged: the messages fold is chrome — search + filters + chips + "Classify all (6)"
  before any mail, first row about mid-screen, "page 1 of 37" framing.
- Worst single defect: the log ERROR path still ships `RuntimeError("SELECT INBOX failed: …")`
  verbatim (engine.py:1594) while the prose formatter already exists one call away.
- Next-most-load-bearing: failure triage (9 vs 1 across two screens, nothing actionable per
  failure) and the missing reply-queue mode for the 10-message needs-reply set.
