## Top gaps vs the commercial bar

1. **persisting — there is still no keyboard or command surface on desktop.** Verified today: the only keydown handlers in `app.py` remain Escape (disarm/close), Enter (submit/send) and the rail-resize grip arrows (1236, 1263, 1485, 1967, 4558); the only row-level keydown in the repo is the plugin SDK list widget accepting Enter/Space (sdk/ui.js:210, 258) — not triage bindings. Best: Fastmail's single-key model (`j`/`k`, `x`, `d`, `y`, `[`/`]`, `z` = undo last 10) and Superhuman's Cmd+K, "your master control for any action" (P1 §2, bar = ≥5 single-key actions). Why it matters for a triage app: on a 1440px desktop, triage speed *is* keyboard speed; mouse-only is the single largest distance between this and the products it borrows its look from.
2. **persisting — snooze cannot express the one intent people actually have.** Presets are fixed durations, 24 / 72 / 168 hours, in both the viewer and the rail (6699, 6828–6830). Best: Gmail/Spark clock-anchored presets, Shortwave's AI-suggested times (P1 §2). Why it matters: "1 day" returns mail at an arbitrary hour; the needs-reply queue is exactly where "tomorrow 9am" / "weekend" does its work.
3. **persisting — search still cannot become a rule or a saved view.** The messages surface offers Search + "More filters" (Sender / Category / Folder, 6299–6304) and the rules page offers only "New rule"; nothing takes today's search and turns it into a rule or a Split. Best: Fastmail (any search result becomes a rule) and Gmail (build a filter from criteria, test the search first), plus Shortwave's custom-query Splits (P1 §1, P2 §2, [11][12]). Why it matters: this is the loop that makes a triage app quieter over time, and the evidence is already on screen the moment a search returns 37 pages of noise.
4. **persisting — undo lives a page away from the mutation.** Machine-filing undo is real (undo_log, store.py:373; dashboard "Recent filings" card with an Undo button, 2631–2641) but it is only reachable from the dashboard; the viewer's own audit trail is collapsed by default, and classifier/rule toggles and category corrections carry no undo at all. Best: Gemini gates agentic actions with confirm plus a 60s undo right where you confirmed (P1 §5 (c)/(d), bar (c) "60s floor"). Why it matters: approve-then-regret is the one real risk of agentic filing; if reversal requires finding the change elsewhere, every approval gets heavier.
5. **new — deterministic fast-paths can be switched on with no dry-run scorecard, while rules have two.** Classifiers run *before* the LLM ("Deterministic heuristic models that run before the LLM") and both visible ones are ON, carrying WEAK labels; the only evidence offered is `n=` counts and a Dataset link — there is no "test against the last 200 messages" for a heuristic, although the rules page has exactly that affordance. Best: Gmail (verify matches with Search before committing) and Outlook ("Run this new rule now on messages already in the current folder") — P2 §2, [11][13]. Why it matters: these fast-paths bypass the model that everything else is validated against; enabling one changes filings silently and the user has no way to preview the blast radius.

## Nits

1. **major — messages — nothing recedes and unread is unrepresentable.** Every row renders the same bold-blue subject; no read/seen state exists in the schema (grep: no read field; "unread" only in an assistant prompt, 7789), so SORTED 2608 and NEW 2 look identical in the list. Source: P1 §1 THE BAR ("unmistakable unread affordance; read items recede"), Spark's Seen section. Fix: derive a recessed style from status (processed rows dim; NEW/ERROR keep full weight).
2. **major — messages — dominating sender is never collapsed.** Two adjacent `notifications@instructure.com` rows (and two `calendar@ust.hk` on the dashboard card) occupy four rows of the fold where HEY would show one collapsed row. Source: P1 §1 (HEY dominating sender; Shortwave Bundles). Fix: collapse repeated sender within a window into one expandable row.
3. **minor — messages — the snippet starts with tracker boilerplate.** Row 3's preview is "If you can't read this email, click here <https://hkust.edu.hk/news/…>" — the first ~110 chars of the one line meant to say what the mail is about. Source: P1 §1 row anatomy (the snippet earns its line). Fix: strip quoted/boilerplate lines and bare URLs before clipping.
4. **minor — dashboard — the attention panel is untimestamped and treats failure as ordinary chrome.** "9 failed messages" uses the same blue badge as navigation, in a panel with no "as of HH:MM"; a failure worth surfacing deserves the red 5xx treatment and a time (Vercel convention, P2 §1, [16]). Fix: red/amber "failed" treatment + panel timestamp.
5. **minor — viewer — snooze and needs-reply render twice with two vocabularies.** Workbench "Snooze" `<details>` (6699) vs the rail's "1 day / 3 days / 1 week" buttons (6828–6830); same actions, two presentations. Source: P2 §8 (states and micro-details deliberate). Fix: one canonical control, the other a state mirror.
6. **minor — viewer — no Reply-all or Forward.** Verified by grep: no forward control in the templates; the workbench offers "Draft reply" alone (6694 area). Source: P1 §3 bar (reply / reply-all / forward). Fix: expose both in the workbench.
7. **minor — rules — no per-rule fire history.** You can dry-run the whole list ("Test against last 200 messages") but cannot see whether rule #6 has ever fired, or when. Source: P2 §2 (Zapier's Zap History logs every run, [15]). Fix: last-fired + match-count column per rule.
8. **minor — classifiers — "↓ REMOVED" samples are dateless and reasonless.** `376 ↓ REMOVED` (3484) says a count, not when or why. Source: P2 §1 (untimestamped data). Fix: hover/expand with date + reason.
9. **minor — classifiers — internal vocabulary is shown as the classifier's own verdict.** Evidence reads `body contains 'sean' → __other__ (100%, n=95)`, so the only learner-facing explanation of a deterministic classifier speaks in `__other__`. Source: P2 §1 (state meaning, not mechanism) / §8. Fix: render as "other (not Newsletter)" and gloss the confidence as "matches N of M samples".
10. **nit — settings — remote images is a checkbox where the app's control language is the switch.** The classifier rows and the proxy/filing toggles use the blue switch; this one setting breaks the pattern. Source: P2 §8. Fix: use the same switch component.
11. **nit — accounts — mechanism words where meaning belongs, and no per-account check.** "loopback mode" and the global "Last check 23s ago" in the sidebar leave the account card without its own freshness or a check action. Source: P2 §1 (state + next action) / P1 §6 (visible freshness + manual refresh). Fix: plain-language sub + per-account "Check now".
12. **nit — assistant — truncated titles repeat, so saved chats collide.** Two "Find me messages..." and two "What rules would you..." in today's list, distinguishable only by date. Source: P2 §8. Fix: append HH:MM and keep the full title as the row label.
